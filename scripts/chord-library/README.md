# Chord library source

The chord shapes unstrung ships. Nothing in this folder is packaged; `scripts/build-chord-library.mjs`
(`npm run build:chords`, also run by the pre-commit hook) reads `voicings.json` and writes
`src/assets/chords/chord-library.json`, which is what the app loads. Edit the shapes here, never in
`chord-library.json`.

## voicings.json

One entry per chord, by `root` and `suffix`, with one voicing to a line:

```json
{"frets":[-1,3,2,0,1,0],"fingers":[0,3,2,0,1,0],"barres":[],"from":"tabsy-gr/chords-db","id":"guitar/C/major/1"}
```

- `frets`: string 6 first. -1 not played, 0 open, otherwise the fret counted from the nut.
- `fingers`: in the same order. 1 index, 2 middle, 3 ring, 4 little, 0 for none. No thumb: any
  other value stops the build.
- `barres`: the frets held by a barre. The build works out which strings each one covers.
- `from`: where the shape came from, and `id`: its id there. The fork's ids never change, so a
  shape can be looked up in its `UPSTREAM-DIFF.md` and `data/changes.json`.
- `forkId`, on a shape of ours from chords-db 0.5.1: the fork voicing it stands in for. The 27
  where the fork's only fingering used the thumb ship this way.

Every fretted string needs a finger; the build stops otherwise. A barre is the strings its finger
holds at that fret, so a string there played by another finger is not under it. A muted string
inside a barre, as in F6 1x3231, is described as damped under the barre.

The suffix must be one `CHORD_FORMULAS` in `src/shared/musicTheory.mjs` knows. The build checks every
voicing against its chord's formula and drops and reports any that sound a note outside the chord or
leave out its seventh. Leaving out other notes, most often the fifth, is allowed.

Voicings are ordered by the build, canonical shapes first and then lower on the neck. Where two tie,
the order in this file is kept, which is the fork's, easiest first. Power chords are generated by the
build; the source's own power chords are kept only where the generator does not make the same shape.

## voicings-to-review.json

Shapes not shipped, each with `reason`. The build does not read this file. A shape moved to
`voicings.json` is checked there like any other. An entry settled by a decision keeps its place and
gains `resolved`, with the date and a note, so the reasoning is there for the next source compared
with this one; an entry without it is still open. As of 2026-11-02, 723 voicings, 665 resolved:

- 43 of the fork's that use the thumb. Resolved: unstrung has no thumb fingerings.
- 117 of the fork's whose type unstrung had no formula for: 7#11, (b5), and 7sus2 over a bass note.
  Resolved: the three were given formulas and these ship.
- 483 of chords-db 0.5.1's, the shapes unstrung shipped before 2026-11-02, that do not ship
  unchanged. Each has `forkId`, the fork voicing that replaced it, where there is one, and the fork's
  change number and reason: 345 changed, most of them by putting the root lowest (change 51); 65
  with other fingers; 25 filed under another chord; 3 removed; 45 that chords-db itself changed
  between 0.5.1 and 0.6.0, with no reason recorded. Resolved: the 346 the fork changed to put the
  root lowest, its version shipping instead, except the taught shapes the build lists as canonical,
  such as Cmaj7 332000, which stay open. Also resolved: the 27 where the fork's only fingering
  used the thumb, shipped in voicings.json with ours, finger 1 across the barre; and the fork's 81
  other corrections, 25 relabelled 7#11, 29 that sound a wrong note, a C9 fret fix and 26
  refingerings with a recorded reason. Still open: the 57 that chords-db itself changed in 0.6.0
  with no reason recorded, 45 changed or dropped and 12 refingered.
- 80 from chords-db 0.5.1 that failed the check or had no formula in 2026-11. Resolved: its 48
  alt, major flat-five triads the fork ships as (b5), and its 3 7sg, a name unstrung does not know.

## Where this came from

- chords-db 0.5.1 (https://github.com/tombatossals/chords-db, MIT), the npm package, was read on
  every build until 2026-11-02. Its shapes were then copied here once and the dependency removed.
- The same day, the file was re-seeded from tabsy-gr/chords-db (https://github.com/tabsy-gr/chords-db,
  MIT) at commit 43f8b4a of 2026-10-13: a fork of chords-db's unpublished 0.6.0 that documents and
  corrects it. Not a dependency either; a later version can be compared with this one by id.

See `docs/chord-library-maintenance.md`.
